All notable changes to olive-css are recorded in this file, in the spirit of
[[https://keepachangelog.com/en/1.1.0][Keep a Changelog]].  Entries are grouped
by the release they belong to, and releases correspond to the repository's git
tags.  See [[file:README.org][the README]] for installation, usage and the
feature reference.

* Unreleased

Work that lands after =v0.8.1= is recorded here until it is tagged.

** Added

- *Background image utilities.*  =bg-center=, =bg-cover=, =bg-repeat-x=,
  =bg-fixed=, =bg-clip-text= and =bg-origin-content= position, size, repeat,
  attach, clip and mask an image.
- *Scroll spacing.*  =scroll-m-*= and =scroll-p-*= (plus the axis and side
  forms) clear sticky headers when an anchor is followed, on the same numeric
  and t-shirt scale as margin and padding.
- *Gradients.*  =bg-linear-to-*= and the familiar =bg-gradient-to-*= aliases,
  plus =bg-radial= and =bg-conic=, consume =--olive-gradient-stops=.  The
  =from-*=, =via-*= and =to-*= families supply those stops from the palette
  shades, =white=, =black= and =transparent=.
- *Color scheme.*  =scheme-normal=, =scheme-light=, =scheme-dark=,
  =scheme-light-dark=, =scheme-only-light= and =scheme-only-dark= set the
  =color-scheme= property, including the =only light= / =only dark= forms.

* v0.8.0 - 2026-11-07

Nothing yet.

* v0.8.1 - 2026-11-07

** Added

- *A command line of its own.*  ~olive-css~ is now the way to generate and
  prune stylesheets.  ~olive-css generate~ writes one shipped build or all of
  them, ~olive-css tree-shake~ prunes a build against a site's HTML, and
  ~olive-css list~ prints the builds.  The project presets moved out of
  =scripts/olive-css-gen.scm= into ~(olive-css builds)~, so a build is data the
  CLI, a program and a test can all use; both scripts are gone and
  ~maak build~ / ~maak tree-shake~ call the CLI instead.
- *A release task.*  ~maak release~ turns the changelog's Unreleased section
  into a dated release, writes the version into every recipe, commits, tags,
  pushes and publishes the GitHub release.  It refuses to run on a dirty tree,
  off =trunk=, or on a version that already has a tag, and it refreshes the
  Arch checksum from the archive the new tag serves.

- *A libre typographic default.* =font-mono= now names JuliaMono, =font-sans=
  names Work Sans and =font-serif= names Source Serif 4, all three under the
  SIL Open Font License and self-hosted by each project  (see [[file:docs/fonts.org][the fonts guide]]).  The previous stacks named two families that are gone from the
  defaults and from every per-project build in ~(olive-css builds)~, which now
  inherit them: a proprietary one that
  shipped with some systems, and a monospace face that was fetched from a font
  service.  Each stack falls back to the system's own monospace, sans and
  serif faces, so a build that serves no font files still renders.
- *Zero on the numeric scale.* The scale now starts at =0=, so the numeric
  families can express an explicit zero: =m-0=, =mx/my/mt/mb/ml/mr-0=,
  =p-0= and the other padding sides, =space-x/y-0=, =gap-0= and =gap-x/y-0=,
  =w-0=, =h-0=, =size-0=, =min-w-0=, =max-h-0=, =border-0= and the per-side
  widths, =divide-x/y-0=, =rounded-0=, =text-0=, =leading-0=, =indent-0=,
  =border-spacing-0=, =stroke-0=, =z-0=, =order-0=, =basis-0=, =flex-0=,
  =brightness-0= and the remaining filters.  The positioning offsets and the
  fixed-width/timing presets, which already had a zero, are unchanged (and no
  longer emitted twice).
- Only the families where a zero count is invalid CSS keep starting at =1=:
  =grid-cols-*=, =grid-rows-*=, =columns-*= and =line-clamp-*= produce no
  =0= step, and neither do the negative =.\-translate-*= utilities.
- ~positive-numeric-sizes~, exported by ~(olive-css sizes)~ for builds that
  need the scale without the zero.

** Fixed

- *The v0.8.0 CLI compiles again.*  The release task left the opening
  parenthesis of =olive-css-version= outside its match, so the form gained a
  second one and the released CLI could not be compiled.  The pattern now
  captures the whole form, with a regression test.

** Changed

- *CI moved to GitHub Actions.*  Pushes to =trunk= now run =maak-test= and
  =maak-deploy= through the Byggsteg reusable workflow in
  =.github/workflows/ci.yml=; the Woodpecker pipeline is gone.
- *MIT licence.*  olive-css is licensed under the MIT licence: =LICENSE=
  replaces =COPYING=, every source file carries a short
  =SPDX-License-Identifier: MIT= header, and the generated stylesheets, the
  documentation, the packaging recipes and the container labels say MIT too.
  The FDL no longer applies to the documentation.
- *The guide lives in =docs/=.*  The README is a landing page again - what
  Olive CSS is, a quick start, install routes and the map - and the details
  moved to [[file:docs/index.org][the documentation index]]: getting started, the CLI,
  building, tree shaking, the full utility reference, the Tailwind comparison,
  fonts and development.  Every page has its own contents list and links back.
- *Packaging ships the command.*  The Debian, openSUSE and Arch recipes install
  =/usr/bin/olive-css=, the licence and the guide, and their test run loads the
  release tool from the project root.  The container's entry point is now
  ~olive-css~ rather than a bare Guile.
- *One version, one home.*  The version is 0.8.0 in the CLI, the Nix
  expression, the openSUSE spec, the Arch recipe and the Debian changelog;
  every recipe names the repository's GitHub home.

* v0.6.0 - 2026-10-11

The first release recorded in this file, and a large one: the utility set grew
from a core of layout, flexbox, spacing, typography and colour into grids,
positioning and sizing, effects, transforms, transitions, interactivity, tables,
SVG and accessibility; state variants became two-tier so =focus:=,
=focus-visible:= and =active:= reach more than colours; and tree shaking moved
out of a standalone script into the library, where it is now covered by a test
suite.  Everything below landed after =v0.4.6= (2026-09-03).

** Added

*** Broader utility coverage

- *Grid:* =col/row-span=, =col/row-start=, =col/row-end=, =auto-rows=, =gap-x/y=.
- *Spacing:* =space-x/y= child spacing, =divide-x/y= child borders and =*-auto= margins such as =mx-auto=.
- *Positioning and sizing:* =inset-x/y=, =start/end=, =size-*=, =dvh/svh/lvh=,
  =w-auto=, =w-fit=, =min/max-content=.
- *Effects:* =opacity-*=, =mix-blend-*=, =bg-blend-*=, =text-shadow-*=,
  =ring-*=/=inset-ring-*= (with colors) and =outline-*=/=outline-offset-*=.
- *Transforms:* =translate-*=, =rotate-*=, =scale-*=, =skew-*=, =origin-*=,
  =will-change-*=.
- *Transitions and animation:* =transition-*=, =duration-*=, =delay-*=, =ease-*=,
  =animate-spin/ping/pulse/bounce=.
- *Interactivity:* the full =cursor-*= set, =select-*=, =pointer-events-*=,
  =resize-*=, =appearance-*=, =field-sizing-*=, =touch-*=, =scroll-smooth=,
  =accent-*= and =caret-*=.
- *Tables and SVG:* =table-*=, =border-collapse/separate=, =border-spacing-*=,
  =caption-*=; =fill-*= and =stroke-*=.
- *Accessibility:* =sr-only= / =not-sr-only=.
- *Borders and radii:* per-side and logical widths (=border-t/r/b/l/x/y=, with
  =border= as the 1px default), =rounded-none= and =rounded-full=.

*** State and responsive variants

- =focus:=, =focus-visible:= and =active:= are generated in two tiers, so the
  interactive states reach typography, transforms and effects while colors stay
  hover-only.  Widen or narrow the coverage with ~state-variants~,
  ~interactive-state-variants~, ~state-variant-targets~ and
  ~interactive-state-targets~.
- =hover:shadow-*= is generated as a state variant.
- Responsive variants now cover the new families: binding ~responsive-classes~ to
  ~core-utility-classes~ gives full structural parity, and adding
  ~color-base-classes~ brings responsive colors such as =md:bg-jeans-blue-700= and
  =lg:text-onyx-500= (both are enabled in the complete prebuilt stylesheets).
- The canonical =dark:hover:= variant order is emitted.

*** Tree shaking

- The pruner now lives in the library module ~(olive-css tree-shaking)~ rather
  than in a standalone script, so it can be driven and extended like the rest of
  the framework.  ~scripts/olive-css-tree-shaking.scm~ is a thin command-line
  front-end over it.
- Every path and search option is a Guile parameter: ~artifact-path~,
  ~base-stylesheet-path~, ~output-css-target~, ~scanned-file-types~ and
  ~skipped-directories~.
- ~(tree-shake)~ returns an association list carrying the destination and byte
  counts, so a build can report the result without parsing console output.  The
  lower-level entry points are exported too: ~scan-used-classes~,
  ~tree-shake-css~, ~parse-css-blocks~, ~serialize-css-blocks~ and
  ~escape-class-name~.
- ~public/sample.html~ is checked in as a fixture, so ~maak tree-shake~ works out
  of the box: it prunes a 4.88 MB build to about 6.6 KB for its 89 classes.

*** Tests

- A [[https://codeberg.org/jjba23/veritas][Veritas]] suite for the tree-shaker lives at
  ~test/veritas/unit/tree-shaking.scm~ and is wired into a new ~maak test~
  task.  It covers class-name escaping, HTML scanning and its options
  (~scanned-file-types~, ~skipped-directories~), de-duplication of repeated
  classes, every pruning rule (media queries, the dark-mode scope, grouping
  rules that become empty, class-free structural rules and selector lists),
  minified output, the ~license-header~ parameter, a parameterized end-to-end
  prune driven by ~artifact-path~ and ~output-css-target~, and a no-leakage
  invariant against ~public/sample.html~: the pruned stylesheet references
  exactly the 89 classes that fixture uses, none leaked and none missing.
- The suite builds its fixtures under ~/tmp~ and removes them afterwards, so
  running it leaves no untracked files behind.  It reads the checked-in
  ~resources/css/olive.min.css~ and the ~public/sample.html~ fixture, and every
  assertion is derived from them, so regenerating the prebuilt stylesheets with
  a narrower feature set does not invalidate it.

** Changed

- Generated stylesheets are *minified by default*: no indentation, no newlines
  between rules and no whitespace after separators.  Bind ~(minified? #f)~ while
  debugging to get readable output back.
- State variants are emitted as plain, flat CSS (=.hover\:bg-x:hover=,
  =.focus\:ring-2:focus=) instead of nested =&:hover= rules, so the output no
  longer depends on CSS nesting.  The dark-mode scope is a single
  =:where([data-theme=dark], [data-theme=dark] *)= group.
- The tree-shaker *parses* the stylesheet into nested blocks rather than matching
  lines, so it prunes inside media queries and the dark-mode scope, keeps the
  structural rules (reset, =@keyframes=, =@view-transition=) that carry no class,
  and drops grouping rules that become empty.
- The license header now lives in its own dependency-free module,
  ~(olive-css license)~, which ~(olive-css main)~ re-exports for compatibility.
  The tree-shaker imports only that module, so pruning no longer loads the
  generator or the ~decl~ modules, and the pruned stylesheet still carries the
  same full header instead of a second, shorter copy.

** Fixed

- Repaired the reset's =border-collapse= (a typo meant tables never collapsed).
- Removed a dead duplicate =content= declaration and a duplicated
  =list-style-type= generation.
- =m-*=, =p-*=, =mx/my/px/py= now use single logical-shorthand rules instead of
  four redundant rules per class.
