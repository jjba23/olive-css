* At a glance
:PROPERTIES:
:CUSTOM_ID: at-a-glance
:END:

| Feature          | Tailwind CSS                               | Olive CSS                                                |
|------------------+--------------------------------------------+----------------------------------------------------------|
| Written in       | JavaScript                                 | λ Guile Scheme                                           |
| License          | MIT                                        | ✔️ MIT, for code, generated CSS and documentation        |
| Customization    | Average (via CSS/JS config)                | ✔️ Extensive (via code and an expressive DSL)            |
| Functional API   | ❌                                         | ✔️                                                       |
| Utility coverage | Broad                                      | ✔️ Broad (see the parity estimate below)                 |
| State variants   | A fixed set, JIT-generated                 | ✔️ Tunable (hover, focus, active, ... via parameters)    |
| Responsive       | All utilities, on demand                   | ✔️ All utilities (full set is opt-in to keep builds lean)|
| Output control   | Limited; the JIT constrains what you get   | ✔️ Full (generate exactly what you want)                 |
| Output size      | Small (JIT emits only used utilities)      | ✔️ Minified + content-aware tree-shaking (a few KiB)     |
| Reproducibility  | Node/npm toolchain                         | ✔️ GNU Guix, bit-for-bit reproducible builds             |
| Paid features    | ❌ Enterprise/Tailwind UI behind a paywall | ✔️ Everything in the source code, for everyone           |

Olive CSS is not another Tailwind clone.  It borrows the class-name syntax and
then hands the generator to you: a build is a Scheme program, and every family
can be inspected, disabled or extended.  That is the trade: you can change
anything, and you are expected to read the code that generates it.

* Estimated feature parity
:PROPERTIES:
:CUSTOM_ID: parity
:END:

How close is Olive CSS to Tailwind's utility surface?  The figure below is an
/estimate/ based on the Tailwind v4 core utility families - an unweighted
average of the category coverage underneath.  It is a useful gauge of where the
gaps are, not a formal audit:

#+begin_example
Estimated feature parity with Tailwind CSS: ~83%
#+end_example

| Category                | Coverage | Main gaps                                                          |
|-------------------------+----------+--------------------------------------------------------------------|
| Layout                  | ~95%     | -                                                                  |
| Flexbox & grid          | ~90%     | space/divide =reverse=                                             |
| Spacing                 | ~85%     | space/divide reverse                                               |
| Sizing                  | ~85%     | named container widths (max-w-sm ... max-w-7xl)                    |
| Typography              | ~90%     | content-* / list-image-* pseudo utilities                          |
| Backgrounds             | ~90%     | mask utilities and gradient alpha stops                            |
| Borders                 | ~90%     | logical border-s/e, divide colors/reverse                          |
| Effects                 | ~65%     | shadow-color, mask-*                                               |
| Filters                 | ~70%     | hue-rotate, drop-shadow, filter-none, backdrop-opacity             |
| Tables                  | ~100%    | -                                                                  |
| Transitions & animation | ~100%    | -                                                                  |
| Transforms              | ~65%     | 3D (perspective, backface, per-axis rotate/translate)              |
| Interactivity           | ~90%     | -                                                                  |
| SVG                     | ~90%     | stroke-dasharray and friends                                       |
| Accessibility           | ~100%    | -                                                                  |
| Variants                | ~40%     | group/peer/has/not, aria/data, container queries, motion/print/rtl |

_Overall: ~83% (unweighted average of the category estimates above)._

* Where the gaps are
:PROPERTIES:
:CUSTOM_ID: gaps
:END:

The fastest ways to close the gap are mask utilities, extra variants
(group/peer, aria/data, container queries) and gradient alpha stops.  Everything already available is documented in the
[[file:reference.org][utility reference]]; nothing here is promised for a future release.
