* Why prune
:PROPERTIES:
:CUSTOM_ID: why
:END:

The complete stylesheet contains every class, state, variant and breakpoint, so
it is measured in megabytes.  A production page needs a few dozen of those
rules.  The tree-shaker scans the built site, keeps the rules whose selectors
match a class that appears there, and writes the result minified - a 9.1 MB
build becomes about 7 KB for this repository's sample page.

Shrinking the input first is still worth it: choosing the breakpoints, dropping
dark mode and narrowing the palette all reduce what the pruner has to consider,
and they are covered in [[file:customization.org][Customizing a build]].

* How it works
:PROPERTIES:
:CUSTOM_ID: how-it-works
:END:

The pruner lives in ~(olive-css tree-shaking)~.  It imports only
~(olive-css license)~ for the header, so pruning does not load the generator or
the =decl= modules.

1. It scans the directory recursively for the files ~scanned-file-types~ names,
   reads the class names ~scan-mode~ understands, escapes them the way CSS
   escapes them (=hover:bg-x= becomes =hover\:bg-x=, =@sm:flex= becomes
   =\@sm\:flex=) and de-duplicates them.
2. It parses the stylesheet into nested blocks instead of matching lines, so it
   understands rules inside =@media=, =@supports=, =@container=, =@layer= and
   the dark-mode =:where= scope, and drops a grouping block that becomes empty.
3. It keeps a rule when any selector in it references a used class, keeps rules
   that carry no class at all (the reset, =@keyframes=, =@view-transition=), and
   drops a grouping rule that becomes empty.
4. It keeps a rule whose class matches a pattern in ~preserved-patterns~, and
   drops everything else.
5. It writes the result minified, with the same licence header.

**Selectors that name more than one class**

A variant can put two class names in one selector:
=.group:hover .group-hover\:flex=.  Only the utility class is matched - the
=group= and =peer= markers name the element a variant watches, not the target
of the rule - so a page that uses =group= somewhere does not drag every
=group-hover= rule into the output.  The same rule keeps the =divide= and
=space= families, whose selectors carry their one class next to a
=:not([hidden]) ~ :not([hidden])= shape.

* Scanning modes
:PROPERTIES:
:CUSTOM_ID: modes
:END:

~scan-mode~ decides what each file is read for.  Three modes exist:

| Mode       | Reads                                                     |
|------------+-----------------------------------------------------------|
| =html=     | =class="..."= and =className="..."= attributes             |
| =sxml=     | the same, plus SXML =(@ (class "..."))= attributes         |
| =manifest= | no file at all: ~preserved-classes~ is the whole input      |

The default is =html= with ~scanned-file-types~ set to =(".html" ".htm")~.
=manifest= is for an application whose classes are computed at run time; it
pairs with =--keep= on the command line.

#+begin_src shell
# An Artanis or Guix application: the templates are SXML.
olive-css tree-shake --directory _site --mode sxml \
                     --stylesheet resources/css/olive.min.css \
                     --output app.min.css
#+end_src

For SXML, point ~scanned-file-types~ at the template suffixes as well
(=(".html" ".scm")=) or pass them from Scheme; the mode says *what* to read,
the suffixes say *which files*.

* Applications with dynamic class names
:PROPERTIES:
:CUSTOM_ID: dynamic
:END:

A template that builds its class from data - =(string-append "text-" colour
"-500")= - cannot be scanned: the name is not in any file.  Two options cover
it, and they compose.

- *Name the classes.*  ~preserved-classes~ is a list of classes kept as
  written (=text-onyx-500=, not =text-onyx-500= escaped); with =manifest= as the
  mode it is the only input.
- *Name the family.*  ~preserved-patterns~ is a list of regular expressions.  A
  selector survives when one of its class names matches, so
  =text-.*-500= keeps the whole text colour row.

#+begin_src scheme
(use-modules (olive-css tree-shaking))

(parameterize ((artifact-path "_site")
               (scan-mode 'manifest)
               (preserved-classes '("bg-onyx-900" "text-floral-white-100"))
               (preserved-patterns '("text-.*-500")))
  (tree-shake))
#+end_src

Patterns are matched against the class name the way the markup writes it, so a
pattern needs no CSS escaping: =bg-.*/50= works.

* From the command line
:PROPERTIES:
:CUSTOM_ID: cli
:END:

=maak tree-shake= runs the default options.  The CLI is the same command with
paths, a mode and the declared classes of your choosing:

#+begin_src shell
olive-css tree-shake --directory _site \
                     --stylesheet resources/css/olive.min.css \
                     --output app.min.css \
                     --mode sxml \
                     --keep-pattern 'text-.*-500'
#+end_src

The repository ships =public/sample.html= as a fixture, so a prune works out of
the box: it scans that file and writes =public/olive.min.css= (git-ignored).  In
a real project, point =--directory= at the generated site and drop or exclude
the sample so its classes do not reach production.

* From Scheme
:PROPERTIES:
:CUSTOM_ID: parameters
:END:

Every path and search option is a parameter, so a build declares its layout
instead of editing code:

#+begin_src scheme
(use-modules (olive-css tree-shaking))

(parameterize ((artifact-path "_site")
               (base-stylesheet-path "resources/css/olive.min.css")
               (output-css-target "app.min.css"))
  (tree-shake))

;; => ((stylesheet . "resources/css/olive.min.css")
;;     (destination . "_site/app.min.css")
;;     (mode . html)
;;     (used-classes . 89)
;;     (input-bytes . 9065114)
;;     (output-bytes . 7153))
#+end_src

~tree-shake~ returns that association list, so a build script can report the
result without parsing console output.  The lower-level entry points are
exported as well: ~scan-used-classes~, ~tree-shake-css~, ~parse-css-blocks~,
~serialize-css-blocks~, ~escape-class-name~, ~unescape-class-name~,
~html-classes~ and ~sxml-classes~.  ~tree-shake-css~ takes ~#:patterns~ for a
one-off prune with patterns; ~tree-shake~ also takes ~#:stylesheet~,
~#:directory~ and ~#:target~.

* Every option
:PROPERTIES:
:CUSTOM_ID: options
:END:

| Parameter              | Default                         | Meaning                                                |
|------------------------+---------------------------------+--------------------------------------------------------|
| ~artifact-path~        | ~"public"~                      | directory of built files to scan (searched recursively) |
| ~base-stylesheet-path~ | ~"resources/css/olive.min.css"~ | compiled stylesheet to prune                           |
| ~output-css-target~    | ~"olive.min.css"~               | output file name, resolved inside ~artifact-path~       |
| ~scanned-file-types~   | ~(".html" ".htm")~              | file suffixes considered when scanning                 |
| ~skipped-directories~  | ~(".git")~                      | directories never descended into                       |
| ~scan-mode~            | ~'html~                         | =html=, =sxml= or =manifest=                           |
| ~preserved-classes~    | ~'()~                           | classes kept as written, found or not                  |
| ~preserved-patterns~   | ~'()~                           | regular expressions; a matching class name is kept     |

* Tests
:PROPERTIES:
:CUSTOM_ID: tests
:END:

A [[https://codeberg.org/jjba23/veritas][Veritas]] suite for the pruner lives at
~test/veritas/unit/tree-shaking.scm~ and runs with ~maak test~.  It covers
class-name escaping (including the =@= of a container variant), HTML scanning
and its options, the three modes, de-duplication, the pruning rules, selectors
that name more than one class, minification, the ~license-header~ parameter, a
parameterized end-to-end prune, and a no-leakage invariant: the stylesheet
pruned for ~public/sample.html~ references exactly the classes that fixture
uses, none leaked and none missing.  The suite builds its fixtures under =/tmp=
and removes them when it finishes.
