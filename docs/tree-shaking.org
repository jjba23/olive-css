* Why prune
:PROPERTIES:
:CUSTOM_ID: why
:END:

The complete stylesheet contains every class, state and breakpoint, so it is
measured in megabytes.  A production page needs a few dozen of those rules.  The
tree-shaker scans the built HTML, keeps the rules whose selectors match a class
that appears there, and writes the result minified - a 5.2 MB build becomes
about 7 KB for this repository's sample page.

Shrinking the input first is still worth it: choosing the breakpoints, dropping
dark mode and narrowing the palette all reduce what the pruner has to consider,
and they are covered in [[file:customization.org][Customizing a build]].

* How it works
:PROPERTIES:
:CUSTOM_ID: how-it-works
:END:

The pruner lives in ~(olive-css tree-shaking)~.  It imports only
~(olive-css license)~ for the header, so pruning does not load the generator or
the =decl= modules.

1. It scans the directory recursively for =.html= and =.htm= files, reads every
   =class= attribute, escapes the names the way CSS escapes them
   (=hover:bg-x= becomes =hover\:bg-x=) and de-duplicates them.
2. It parses the stylesheet into nested blocks instead of matching lines, so it
   understands rules inside =@media=, =@supports=, =@layer= and the dark-mode
   =:where= scope.
3. It keeps a rule when any selector in it references a used class, keeps rules
   that carry no class at all (the reset, =@keyframes=, =@view-transition=), and
   drops a grouping rule that becomes empty.
4. It writes the result minified, with the same licence header.

* From the command line
:PROPERTIES:
:CUSTOM_ID: cli
:END:

=maak tree-shake= runs the default options.  The CLI is the same command with
paths of your choosing:

#+begin_src shell
olive-css tree-shake --directory _site \
                     --stylesheet resources/css/olive.min.css \
                     --output app.min.css
#+end_src

The repository ships =public/sample.html= as a fixture, so a prune works out of
the box: it scans that file and writes =public/olive.min.css= (git-ignored).  In
a real project, point =--directory= at the generated site and drop or exclude
the sample so its classes do not reach production.

* From Scheme
:PROPERTIES:
:CUSTOM_ID: parameters
:END:

Every path and search option is a parameter, so a build declares its layout
instead of editing code:

#+begin_src scheme
(use-modules (olive-css tree-shaking))

(parameterize ((artifact-path "_site")
               (base-stylesheet-path "resources/css/olive.min.css")
               (output-css-target "app.min.css"))
  (tree-shake))

;; => ((stylesheet . "resources/css/olive.min.css")
;;     (destination . "_site/app.min.css")
;;     (used-classes . 89)
;;     (input-bytes . 5217393)
;;     (output-bytes . 7059))
#+end_src

~tree-shake~ returns that association list, so a build script can report the
result without parsing console output.  The lower-level entry points are
exported as well: ~scan-used-classes~, ~tree-shake-css~, ~parse-css-blocks~,
~serialize-css-blocks~ and ~escape-class-name~.  ~tree-shake~ also takes
~#:stylesheet~, ~#:directory~ and ~#:target~ for a one-off run.

* Every option
:PROPERTIES:
:CUSTOM_ID: options
:END:

| Parameter              | Default                         | Meaning                                                |
|------------------------+---------------------------------+--------------------------------------------------------|
| ~artifact-path~        | ~"public"~                      | directory of built HTML to scan (searched recursively) |
| ~base-stylesheet-path~ | ~"resources/css/olive.min.css"~ | compiled stylesheet to prune                           |
| ~output-css-target~    | ~"olive.min.css"~               | output file name, resolved inside ~artifact-path~      |
| ~scanned-file-types~   | ~(".html" ".htm")~              | file suffixes considered when scanning                 |
| ~skipped-directories~  | ~(".git")~                      | directories never descended into                       |

* Tests
:PROPERTIES:
:CUSTOM_ID: tests
:END:

A [[https://codeberg.org/jjba23/veritas][Veritas]] suite for the pruner lives at
~test/veritas/unit/tree-shaking.scm~ and runs with ~maak test~.  It covers
class-name escaping, HTML scanning and its options, de-duplication, the pruning
rules, minification, the ~license-header~ parameter, a parameterized end-to-end
prune, and a no-leakage invariant: the stylesheet pruned for
~public/sample.html~ references exactly the classes that fixture uses, none
leaked and none missing.  The suite builds its fixtures under =/tmp= and removes
them when it finishes.
